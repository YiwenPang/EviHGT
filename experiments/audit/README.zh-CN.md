# R0 对比实验审计

[English](README.md)

[分折台账](r0_fold_audit.csv)记录了原六种方法对比中按方法、数据折和输出通道组织的全部 55 项结果。它包含汇总计数、排序后（药物、疾病、P/U 角色）三元组的 SHA-256、可评估疾病数和三个折级指标。每行通过校验值关联原始指标文件和完成凭证。HGTDR 的 R0F0 使用了较早的缓存，指标文件头缺少面板校验值。台账中的摘要以所选第 222 个 epoch 保存的候选为依据重新计算。

在仓库根目录执行公开一致性检查。

```sh
python experiments/audit/verify_r0.py
```

如果本地保留了原始结果目录，以下命令还能核对产物摘要和候选身份，并从保存的逐疾病指标复算各折的宏平均 ROC-AUC、AP 和 NDCG@10。验证程序可利用原生模型保存的逐候选分数重建相应的面板摘要。

```sh
python experiments/audit/verify_r0.py --research-root /path/to/original/EviHGT
```

验证程序能唯一定位本地 R0 指标审计文件时，会直接使用该文件。也可以通过 `--artifact-index PATH` 指定此文件。若缺少索引或发现多份而无法确定，包含归档提交的 Git 克隆可以依据已记录的台账恢复产物的原始位置。各种方式都使用公开的文件校验值和面板标识。

<a id="how-to-interpret-the-comparison"></a>

## 如何解读对比结果

- 在同一数据折内，对每个可用的输出通道都用相同候选评分。正例是对应类型的已记录关系，U 表示抽样得到的未标注药病对。源数据处理中排除了目标对的直接事实、反向事实和等价事实。预训练编码器在上游训练中是否接触过目标信息仍待核实。
- FULL、HGT-D1 和 PairMLP-D1 共用节点输入、采样、损失和固定更新预算。三者的架构和实际计算有差别。FULL 在全部五折的治疗支持 AP 都高于两种匹配对照。
- HGTDR 适配版从 300 个 epoch 中选模，优先看内层开发集的治疗支持 ROC-AUC，再比较 AP。TxGNN 适配版使用一个预训练 epoch 和 500 个微调 epoch，有 20 次基于治疗支持指标的选模机会。禁忌证评分沿用按治疗支持指标选出的权重。这些系统比较使用各自选模时的开发面板。原对比中，HGTDR 适配版的治疗支持 AP 最高。单独使用禁忌证训练的 HGTDR 适配版有独立的选模流程和结果记录。
- Popularity 对每个输出通道分别按药物在训练正例中的出现频次评分。在台账记录的原六方法对比中，Popularity 的禁忌证 AUC 和 NDCG@10 最高。按疾病优先汇总时，匹配的 HGT-D1 的禁忌证 AP 最高。按折优先汇总时，这组方法的禁忌证 AP 也由 Popularity 排首位。扩展后的主表加入后来单独训练的 HGTDR-adapted-contra，由它在这三项禁忌证指标上领先。解读该任务时需要考虑候选构成及同一疾病在多个数据折中的覆盖情况。
- 主要结果先按疾病在其可评估折内取平均，再对疾病等权汇总。这里的 55 行是折级汇总。复算主表需要用逐疾病结果。五折存在重叠，据此进行描述性比较。
